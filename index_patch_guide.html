🔧 A.U.R.A index.html 패치 가이드

Lv.1 보안 패치 적용 — 기존 index.html에 auth.js 도입 절차 (개발자용)
📌 적용 전 체크리스트
이 가이드는 본 보고서에 동봉된 login.html(신규)과 auth.js(신규)를 기존 index.html과 연동하는 절차입니다. 적용 전 반드시 현행 운영 파일을 백업하세요.

STEP 1 파일 배치

아래 4개 파일을 같은 폴더에 배치합니다.

📁 aura/
├── login.html      // 신규 — 본 보고서 동봉
├── auth.js         // 신규 — 본 보고서 동봉
├── index.html      // 기존 — 아래 절차로 수정
└── (기타 자산)

STEP 2 index.html 수정 — <head> 영역

<head> 태그 최상단에 auth.js를 추가합니다. 다른 어떤 스크립트보다 먼저 로드되어야 인증 우회를 차단할 수 있습니다.

변경 전 (index.html, 6~10번째 줄)

<head>
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<title>A.U.R.A v5.2 - 울산공항 활주로 살수 자동화</title>
<script src="https://cdnjs.cloudflare.com/ajax/libs/Chart.js/..."></script>

변경 후

<head>
<meta charset="UTF-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<title>A.U.R.A v5.2 - 울산공항 활주로 살수 자동화</title>
<script src="auth.js"></script>  <!-- ★ 추가: 인증 가드 (다른 스크립트보다 먼저) -->
<script src="https://cdnjs.cloudflare.com/ajax/libs/Chart.js/..."></script>

STEP 3 기존 인증 코드 제거

현행 index.html에는 두 군데의 자체 인증 코드가 있습니다. 모두 제거합니다.

제거 대상 ① — 604~608번째 줄 부근

// ── 비밀번호 인증 확인 ──────────────────
if (sessionStorage.getItem('aura_auth') !== 'aura6332') {
  window.location.replace('login.html');
}

→ 위 4줄을 통째로 삭제합니다. (auth.js가 동일 기능을 안전하게 수행)

제거 대상 ② — 2155~2190번째 줄 부근의 checkAuth() 함수 전체

// ════════════════════════════════════════
//  비밀번호 보호
// ════════════════════════════════════════
var PW_CORRECT = 'aura6332';
var PW_KEY = 'aura_auth_v1';

function checkAuth() {
  // ... (전체 함수 30+ 줄)
}

→ 함수 전체를 통째로 삭제합니다.

제거 대상 ③ — 2193번째 줄

// ── 초기 실행 ──────────────────────────
checkAuth();   // ← 이 한 줄만 삭제
refreshKeyStatus();

STEP 5 로그아웃 버튼 추가 (권장)

운영자 교대 시 명시적 로그아웃 기능 제공을 위해 헤더에 버튼을 추가합니다.

변경 전 (header 영역)

<button class="btn-hdr" onclick="openSettings()">⚙️ API 설정</button>

변경 후

<button class="btn-hdr" onclick="openSettings()">⚙️ API 설정</button>
<button class="btn-hdr" onclick="AURA_logout()">🚪 로그아웃</button>  <!-- ★ 추가 -->
💡 AURA_logout() 함수는 어디서 왔나?
auth.js 가 페이지 로드 시 자동으로 window.AURA_logout 을 등록합니다. 별도 정의 없이 onclick에서 바로 호출 가능합니다.

STEP 6 검증 시나리오

패치 적용 후 아래 6개 시나리오를 반드시 테스트합니다.

  • S1. login.html에서 정상 비밀번호 입력 → index.html 진입 ✓
  • S2. login.html에서 5회 오입력 → 5분 잠금 표시 ✓
  • S3. 로그인 안 한 상태로 index.html 직접 URL 입력 → login.html 자동 리다이렉트 ✓
  • S4. 콘솔에서 sessionStorage.setItem('aura_auth','aura6332') 후 새로고침 → 접근 불가 (구 키 무효화) ✓
  • S5. 8시간 경과 후 자동 로그아웃 동작 (타이머 단축으로 검증 권장) ✓
  • S6. 헤더의 로그아웃 버튼 클릭 → login.html로 이동 + 세션 삭제 ✓

STEP 7 변경 요약

구분변경 전변경 후
비밀번호 저장코드 내 평문 ('aura6332')SHA-256 해시값만 코드 내 존재
세션 키비밀번호 자체를 세션에 저장무작위 토큰 + 만료시각
인증 키 이름2종 혼재 (aura_auth, aura_auth_v1)aura_session 단일
오입력 잠금없음5회 오입력 시 5분 잠금
세션 만료브라우저 종료 시까지 유효8시간 후 자동 만료
인증 코드 위치index.html 내부 분산 (3곳)auth.js 단일 모듈
⚠️ Lv.1의 본질적 한계
SHA-256 해시도 단순 사전공격(rainbow table)에는 취약하며, F12 콘솔에서 sessionStorage 토큰을 직접 위조하는 방식은 여전히 가능합니다. 이는 클라이언트 사이드 인증의 구조적 한계로, 본격 운영 시점에는 반드시 Lv.2(Cloudflare Access) 또는 Lv.3(백엔드 JWT) 도입을 권고합니다.

DONE 적용 완료

이상의 절차로 Lv.1 보안 패치가 적용됩니다. 작업 시간은 약 30분~1시간이 소요됩니다.
